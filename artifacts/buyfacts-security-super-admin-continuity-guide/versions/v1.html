BuyFacts Security & Super Admin Continuity Guide

Robust Asset Protection, Role-Based Access Control, and Succession Planning

1. Robust Authentication & Asset Protection

To prevent unauthorized asset deletion or database corruption, the BuyFacts admin portal implements a strict multi-tier security model:

  • Super Admin: Full privileges, including record deletion, granting roles, and managing administrator accounts. Destructive actions trigger automatic audit logging.
  • Admin: Can create and update database records and view analytics, but cannot delete records or modify user roles.
  • Editor / User: Read-only access to the database explorer.
Automatic Protection: The database deletion API (DELETE /api/admin/database) rejects any deletion request from non-super-admin accounts with a 403 Forbidden, and permanently preserves sensitive tables like User and AuditLog against hard deletion.

2. Key Security Enhancements Added

  • Strong Passwords: Minimum 12 characters, requiring uppercase, lowercase, and numbers via scrypt hashing.
  • Brute-Force Lockout: Accounts automatically lock for 15 minutes after 5 consecutive failed login attempts.
  • Two-Factor Authentication (2FA): Optional TOTP authenticator app support (Google Authenticator, Authy, 1Password) for all admins.
  • Secure Password Reset: Single-use, time-limited tokens (hashed in DB) sent via Resend email.
  • Comprehensive Audit Trail: Every sign-in, permission change, and deletion is recorded in the AuditLog table with actor ID, IP address, and timestamp.

3. Succession Planning: How to Create a New Super Admin When You Leave

When you are no longer available at the company, continuity of super admin control is guaranteed through two secure mechanisms:

Option A: Promotion via an Existing Super Admin (Recommended Daily Operations)

The company should maintain at least two active Super Admins at all times (e.g. founder + trusted lead engineer/CTO).

  1. Sign in to the Admin Portal as a Super Admin.
  2. Navigate to the Security & Access tab.
  3. Under Administrator Accounts, click Add Administrator to create the new team member's account.
  4. Change their role dropdown to super_admin.
  5. The system protects against accidental lockout: it prevents removing the last super admin, ensuring continuity.

Option B: Break-Glass CLI Bootstrap (When All Existing Super Admins are Lost)

If every existing super admin has left the company and no credentials remain, the deployment server has a secure recovery script built-in:

npm run bootstrap-admin -- --email newadmin@company.com --name "New SuperAdmin"
Security Safeguard: If active super admins already exist in the database, the script will refuse to run unless you supply the BOOTSTRAP_ADMIN_FORCE_TOKEN environment variable and --force. This prevents unauthorized privilege escalation attacks.
